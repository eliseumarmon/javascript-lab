# Sesión 08 · Concurrencia y `Promise.all()`

**Objetivo:** diferenciar ejecución secuencial, concurrente, orden de resultados y errores.

Trabaja con [el laboratorio de concurrencia](https://github.com/eliseumarmon/javascript-lab/blob/main/laboratorio/08_concurrencia.js). No hace llamadas de red: `fakeRequest()` simula la duración de solicitudes mediante temporizadores.

## Lectura (10 min)

Explica de memoria por qué `ids.map(id => fakeRequest(id))` crea promesas pendientes y por qué `await` dentro de un `for...of` ralentiza el total.

## Ejercicios (35 min)

**8.1.** Predice el contenido de `result`:
```js
const result = await Promise.all([
  Promise.resolve('A'),
  Promise.resolve('B')
]);
console.log(result);
```
(Escribe este código dentro de una función `async`, o usa un módulo ESM.)

**8.2.** Predice qué ocurre:
```js
const result = await Promise.all([
  Promise.resolve(1),
  Promise.reject(new Error('boom')),
  Promise.resolve(3)
]);
```

**8.3.** Implementa `loadSequential(ids)` en el archivo del laboratorio. Debe devolver las respuestas en orden, iniciando cada petición solo tras la anterior.

**8.4.** Implementa `loadConcurrent(ids)` usando `Promise.all`. Debe conservar el orden original de IDs en el array final.

**8.5.** Implementa `loadSettled(ids)` usando `Promise.allSettled`. Si pasas `[1, 3, 2]`, debe devolver estados de los tres elementos, aunque ID 3 falle.

**8.6.** Explica la diferencia entre «`Promise.all()` falla» y «`Promise.all()` cancela las solicitudes». ¿Por qué no son equivalentes?

**8.7.** Diseña una solución para procesar muchas peticiones de una API limitada a 2 solicitudes simultáneas. No necesitas implementar un scheduler general; sí describir o codificar el enfoque en lotes de dos.

**8.8.** Modifica la función `getUser()` ficticia del laboratorio para que un error de respuesta `!response.ok` se transforme en una excepción, incluso cuando `fetch()` haya resuelto la promesa.

## Corrección (15 min)

Ejecuta `node laboratorio/08_concurrencia.js` desde la raíz de este repositorio. Registra qué operaciones se inician simultáneamente y cuáles no. Consulta el solucionario correspondiente (pendiente de incorporar).
